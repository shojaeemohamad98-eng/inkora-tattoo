# تحویل فاز ۴ — فروشگاه محلی

تاریخ: 2026-09-27. commit پس از بررسی نهایی ثبت می‌شود. ریشه: `C:\Users\moham\Local Sites\inkora tattoo`.

## ساخته‌شده

- مسیرهای RTL و responsive فروشگاه، جزئیات محصول، سبد، تسویه و حساب.
- Home به فهرست واقعی محصولات متصل شد و ورودی جست‌وجو و لینک فروشگاه واقعی دارد.
- Store API client مرکزی با قراردادهای runtime و timeout؛ داده‌های نامعتبر یا خطا جایگزین ساختگی ندارند.
- Mini-cart و سبد واقعی با Cart Token سمت سرور؛ تغییر تعداد و حذف فقط از مسیر واسطهٔ هم‌مبدأ انجام می‌شوند.
- جزئیات محصول HTML خام WooCommerce را render نمی‌کند تا XSS از محتوای محصول وارد UI نشود.
- تسویه فقط خلاصهٔ واقعی سبد را نشان می‌دهد و پیش از انتخاب درگاه سفارش یا پرداخت ایجاد نمی‌کند.

## وضعیت واقعی داده

WordPress و WooCommerce در `http://inkora.test.local` روشن و health endpoint موفق‌اند. تنها محصول فعلی، `INKORA-PHASE-01`، ناموجود و تست داخلی است؛ از catalog عمومی پنهان می‌ماند. دستهٔ Uncategorized نیز تنها همین کالا را دارد و نمایش داده نمی‌شود. در نتیجه Home و Shop حالت خالی صادقانه دارند.

## آزمون‌ها

- Store API health/products/categories/cart واقعی: موفق.
- `pnpm check`: صفر خطا و صفر هشدار.
- `pnpm build`: موفق.
- `pnpm test`: چهار آزمون تبدیل ارز موفق.
- `pnpm verify:live`: موفق؛ محصول تست و ۱۲۵٬۰۰۰ تومان را فقط در integration check تأیید کرد.
- HTTP 200 برای `/`، `/shop`، `/cart`، `/checkout`، `/account`، `/design-system` و `/integration-check`.
- `/api/cart` با سبد خالی واقعی HTTP 200؛ تلاش کنترل‌شده برای افزودن کالای تست ناموجود HTTP 400 مورد انتظار داد و سبد را تغییر نداد.
- مرورگر واقعی: Home در 320px و Shop در 1440px، Cart در 320px دیده شد؛ RTL، لینک‌ها و empty states قابل مشاهده بودند.

## برای ادامه

مدیر فروشگاه باید محصولات واقعی، دسته‌بندی، قیمت/موجودی و تصویرهای مجاز را در WooCommerce همین سایت Local بسازد. برای پرداخت، نام درگاه ایرانی و حساب sandbox لازم است. تا آن زمان افتتاح یا پرداخت واقعی آماده نیست.
